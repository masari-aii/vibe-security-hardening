# Vibe Security Hardening

Model-agnostic and stack-agnostic. Works with any LLM (Claude, GPT, Gemini, Llama, Qwen, DeepSeek...) and any agent or plain chat. No tool names are assumed: "read", "search", "run" mean whatever the host provides. If the host has no file or shell access, ask the user to paste the relevant files and output commands for them to run.

Scope: defensive only, on the user's own project. Never attack third-party systems. Never print secret values; show only name, file, line, and last 4 characters.

Reply in the user's language (Arabic RTL or English).

## Workflow

1. DETECT: stack (open the matching sections of `references/stacks.md`), framework, DB, auth provider, hosting, payment provider, upload paths, and build the sensitive data map (Module E). Read manifests and config first (package.json, requirements.txt, composer.json, .env.example, framework config, DB rules/policies, deploy config).
2. AUDIT: run the scanner first (`python3 scripts/scan.py <project> [--url <own site>]`; if no shell, ask the user to run it and paste the output). Confirm each finding in the code. Then go through all 27 controls and modules E, P, D, plus A (AI apps) and K (Saudi personal data) when they apply. For each: PASS / FAIL / N/A with evidence (file:line). No evidence = not PASS.
3. PLAN: list FAIL items by severity (Critical > High > Medium > Low). Critical = exposed secret, open DB, auth bypass, injection, client-trusted price, sensitive data stored in plaintext.
4. FIX: smallest targeted diff per item. Preserve working functionality. Use the framework's built-in security feature before adding a library. Never weaken a control to make a test pass.
5. VERIFY: re-test each fix (control 27), rerun the scanner until no critical/high findings remain, run build and existing tests. Offer the CI workflow so the scan runs on every push.
6. REPORT: output the report format below.

Ask the user only when blocked: missing credentials, production access, or an irreversible action (key rotation, Git history rewrite, DB migration on live data). Otherwise proceed with safe defaults.

## The 27 controls

### A. Identity and access
1. Secure login: use a vetted auth library/provider; server-side sessions or short-lived signed tokens; generic error messages; lockout/backoff; MFA for admins where available.
5. Password hashing: Argon2id with pepper and the E9 parameters (preferred), else bcrypt/scrypt with per-user salt. Never plaintext, MD5, SHA-1, or reversible encryption. Rehash legacy hashes on next login.
9. Admin pages locked: authorization checked on the server for every admin route and API, deny by default; hiding the link is not protection.
15. Cookies: HttpOnly, Secure, SameSite=Lax or Strict, scoped path/domain, sensible expiry; rotate session ID on login and privilege change.
16. CSRF: anti-CSRF token or framework middleware on every state-changing request using cookie auth; no state change on GET.
17. Password reset: single-use, random (>=128-bit), stored hashed, expires in 15-60 min, invalidated after use or password change; same response whether the email exists or not.

### B. Secrets
2. API keys hidden: no secret in client bundle, repo, or logs; secret calls go through a server endpoint/proxy.
11. Environment variables: separate public from server-only (check prefixes like NEXT_PUBLIC_, VITE_, PUBLIC_, REACT_APP_); .env in .gitignore; provide .env.example with names only; least-privilege keys per environment.
24. Git history: scan full history for secrets (gitleaks or trufflehog if available, else grep history for key patterns: sk-, sk_live, AKIA, AIza, ghp_, xox, -----BEGIN, password=, secret=, token=).
25. Revoke and rotate: any key ever committed or shipped to the browser is compromised. Revoke at the provider, issue a new one, update env, then (with user approval) purge history. Removing the line is not enough.

### C. Data and input
3. Database secured: not publicly reachable; row-level/ownership rules so each user reads and writes only their own rows (RLS / security rules / policy checks); app uses a least-privilege DB user; backups enabled.
6. Server-side validation: every input validated on the server by schema (type, length, range, allow-list). Client validation is UX only.
7. XSS: output encoding by default; no raw HTML sinks (innerHTML, dangerouslySetInnerHTML, v-html, |safe) on user data; sanitize unavoidable rich text with a vetted sanitizer; add CSP.
10. Parameterized queries: prepared statements or ORM bindings everywhere; no string concatenation into SQL/NoSQL/shell; allow-list dynamic identifiers.
18. File uploads: allow-list type by content (magic bytes) not just extension; max size; random server-generated names; store outside web root or in object storage; never executable; scan if available.
19. Prices and payments: server computes price, discount, and total from its own DB; never trust amounts from the client; verify payment via signed provider webhook; idempotency keys; grant access only after verified payment.

### D. Transport and browser
4. Forced HTTPS: redirect HTTP to HTTPS; HSTS (max-age >= 15552000, includeSubDomains); no mixed content.
13. CORS restricted: explicit origin allow-list; never * with credentials; never reflect arbitrary Origin; limit methods and headers.
14. Security headers: Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options: nosniff, frame-ancestors or X-Frame-Options, Referrer-Policy, Permissions-Policy; remove X-Powered-By/Server version.

### E. Abuse and operations
8. Monitoring: log auth events, failures, admin actions, permission denials with timestamp, user, IP; no secrets or passwords in logs; alert on spikes.
12. Rate limiting: per IP and per account on login, signup, reset, OTP, and costly or paid-API endpoints; return 429.
20. Debug off in production: no stack traces, debug toolbars, verbose errors, source maps with secrets, or open API docs/GraphQL introspection; generic error page with a reference ID.
21. Vulnerable dependencies: run the ecosystem audit (npm audit, pip-audit, composer audit, etc.); upgrade or patch High/Critical; commit lockfile.
22. Unused dependencies: remove packages that are not imported.
23. Exposed files: block public access to .env, .git, backups (.bak, .sql, .zip), config, logs, directory listing, default/admin install pages; each must return 403/404.

### F. Review and proof
26. Full security review: after fixes, re-read auth, authorization, data access, and payment flows end to end, looking for IDOR (changing an ID to reach another user's data), missing checks on new endpoints, and business-logic flaws.
27. Test the protection and report: prove each control with a real check against local or staging (never brute-force production). Examples: request admin route unauthenticated -> 401/403; user A requests user B's record -> 403/404; submit `' OR 1=1--` and `<script>alert(1)</script>` -> rejected or encoded; tamper price to 1 -> server rejects; 20 rapid logins -> 429; GET /.env and /.git/config -> 404; request with foreign Origin -> no CORS allow; upload .exe renamed .jpg -> rejected; inspect response headers and cookie flags.

# Automated scanner and CI

`scripts/scan.py` gives repeatable, evidence-based findings in seconds. Run it first in AUDIT and again in VERIFY. Python 3.8+, standard library only; uses `git`, `npm`, `pip-audit`, `composer` when present.

```bash
python3 scripts/scan.py /path/to/project                          # code, git history, dependencies
python3 scripts/scan.py . --url https://your-site.com             # + live headers, cookies, CORS, HTTPS, exposed paths
python3 scripts/scan.py . --json report.json --fail-on high       # CI: exit 1 on high or critical
python3 scripts/scan.py . --no-history --no-deps                  # fast local pass
```

What it checks (each finding names the control):
- Secrets in files and in all git history (AWS, Stripe live, OpenAI, Anthropic, GitHub, Google, Slack, SendGrid, Twilio, private keys, Supabase service_role JWTs, DB URLs with passwords, hardcoded secret assignments). Values are masked to the last 4 characters.
- Tracked sensitive files (`.env`, keys, dumps, backups, credentials JSON) and `.env` missing from `.gitignore`.
- Secret-looking variables behind public prefixes (`NEXT_PUBLIC_`, `VITE_`, `REACT_APP_`, `EXPO_PUBLIC_`, ...).
- Dangerous code: raw HTML sinks, SQL built with interpolation, eval/shell, MD5/SHA-1 passwords, JWT `none`/disabled verification, TLS verification off, CORS `*`, debug on, `Math.random()` tokens, open Firebase rules, insecure cookies, user input in LLM system prompts.
- Supabase/SQL migrations creating tables without `ENABLE ROW LEVEL SECURITY`.
- Dependencies: `npm audit`, `pip-audit`, `composer audit`.
- Live site (only your own): HTTPS redirect, HSTS, CSP and other headers, cookie flags, CORS reflection, version leaks, exposed `/.env`, `/.git/config`, backups, API docs / GraphQL introspection, `security.txt`.

Rules for using results:
- A scanner finding is evidence to confirm, not an automatic verdict: open the file, confirm, then fix. Regex checks miss logic flaws (IDOR, business logic, broken authorization), so the manual 27-control review still runs.
- Any secret found in history is compromised: revoke and rotate (C25) even after deleting it.
- Only scan URLs you own or are authorized to test.

CI: copy `templates/security-scan.yml` to `.github/workflows/security-scan.yml` and `scripts/scan.py` to `.security/scan.py` in the project (a pinned, reviewed copy; do not download it at build time). It runs on every push, pull request and weekly, fails the build on high/critical findings, uploads the JSON report, and scans the live site if the repository variable `SITE_URL` is set.

# Module S — Stack playbooks

Use the section for each technology found in DETECT. Each item maps to a core control (C#) or module item. Always run the stack's own audit tool too.

## Next.js (App Router / Pages)

- C11: only `NEXT_PUBLIC_*` reaches the browser; secrets never get that prefix. Add `import 'server-only'` at the top of modules that read secrets so a client import fails the build.
- C9/C6: Server Actions and Route Handlers are public HTTP endpoints. Inside every one: validate input (zod/valibot) and check the session and the user's right to the specific record. Middleware is an extra layer, never the only authorization check.
- C21: keep Next.js and React patched. Examples: CVE-2025-29927 (middleware authorization bypass via `x-middleware-subrequest`, fixed in 15.2.3 / 14.2.25 / 13.5.9 / 12.3.5) and React2Shell CVE-2025-55182 / CVE-2025-66478 (RCE in React Server Components; upgrade to the patched release in the Vercel React2Shell bulletin). Run `npm audit` and upgrade.
- C14: set headers in `next.config.js`:

```js
const csp = "default-src 'self'; img-src 'self' data: https:; script-src 'self'; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'";
module.exports = {
  poweredByHeader: false,
  productionBrowserSourceMaps: false,
  async headers() {
    return [{ source: '/(.*)', headers: [
      { key: 'Content-Security-Policy', value: csp },
      { key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains; preload' },
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
      { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
    ] }];
  },
};
```
  Tighten `script-src` with nonces if inline scripts are needed.
- C7: `dangerouslySetInnerHTML` only with DOMPurify-sanitized content.
- SSRF: restrict `images.remotePatterns` to known hosts; validate any server-side `fetch(userUrl)` against an allow-list.

## Supabase

- The anon key is public by design; security comes from Row Level Security. The `service_role` key bypasses RLS: server only, never in client code or `NEXT_PUBLIC_*`/`VITE_*`.
- C3: enable RLS on every table in exposed schemas, with explicit policies per operation:

```sql
alter table public.profiles enable row level security;
create policy "read own profile"   on public.profiles for select using ((select auth.uid()) = id);
create policy "update own profile" on public.profiles for update using ((select auth.uid()) = id) with check ((select auth.uid()) = id);
create policy "insert own profile" on public.profiles for insert with check ((select auth.uid()) = id);
-- no delete policy = nobody can delete via the API
```
- Views: `create view ... with (security_invoker = true)` so RLS applies. `security definer` functions: `set search_path = ''` and check `auth.uid()` inside.
- Storage: private buckets with policies on `storage.objects` (e.g. path prefix = `auth.uid()`); signed URLs for downloads.
- Auth: enable email confirmation, leaked-password protection and MFA for admins; disable sign-ups if the app is invite-only; restrict redirect URLs.
- Run the dashboard Security Advisor and fix every error before launch.

## Firebase

- C3: rules are the only server-side guard for client SDK access. Never `allow read, write: if true`.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read:   if request.auth != null && request.auth.uid == userId;
      allow update: if request.auth != null && request.auth.uid == userId
                    && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['name', 'avatar', 'updatedAt']);
      allow create: if request.auth != null && request.auth.uid == userId;
      allow delete: if false;
    }
  }
}
```
- Storage rules by `request.auth.uid` path, size and content type limits.
- Enable App Check; restrict the browser API key in Google Cloud Console (HTTP referrers + allowed APIs); Admin SDK credentials only on the server; test rules with the Emulator Suite.

## Vercel / Netlify / similar hosting

- Env vars scoped per environment (Production / Preview / Development); production secrets not exposed to preview builds of forks.
- Enable deployment protection for previews; custom domain with HTTPS only; headers via framework config or `vercel.json` / `_headers`.
- Put a WAF/firewall rule set and bot protection in front (P1, P2).

## Laravel

- `.env`: `APP_ENV=production`, `APP_DEBUG=false`, strong `APP_KEY`; web root is `public/` only; `php artisan config:cache`.
- C6/C10: Form Requests for validation; Eloquent/Query Builder bindings, never raw concatenation; `$fillable` on models (no `$guarded = []`).
- C7: `{{ }}` escapes; avoid `{!! !!}` with user data.
- C16: keep `VerifyCsrfToken`; C12: `throttle` middleware on login, API and AI routes.
- C5: `config/hashing.php` driver `argon2id`. Module E: `'encrypted'` casts are convenient but use `APP_KEY` for everything; for high-sensitivity fields prefer the E9 per-field keys or at least a separate key.
- Check `php artisan route:list` for routes missing `auth`/policies; `storage/` and logs not web-accessible.

## Django

- `DEBUG=False`, `SECRET_KEY` from env, `ALLOWED_HOSTS` set; `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, `SECURE_HSTS_SECONDS=31536000`, `SECURE_HSTS_INCLUDE_SUBDOMAINS`, `SECURE_CONTENT_TYPE_NOSNIFF`; run `python manage.py check --deploy` and fix all warnings.
- C5: `PASSWORD_HASHERS` with `Argon2PasswordHasher` first (`pip install argon2-cffi`).
- C10: ORM; `raw()`/`extra()` only with params. C7: avoid `|safe` and `mark_safe` on user data.
- Admin: non-default URL, MFA (e.g. django-otp), staff accounts minimal.

## Express / Node.js APIs

```js
import helmet from 'helmet';
import rateLimit from 'express-rate-limit';
import cors from 'cors';
app.disable('x-powered-by');
app.set('trust proxy', 1);                       // real hop count behind your proxy/CDN
app.use(helmet());
app.use(cors({ origin: ['https://app.example.com'], credentials: true }));
app.use(express.json({ limit: '100kb' }));
app.use('/api/auth', rateLimit({ windowMs: 15 * 60 * 1000, limit: 20 }));
```
- Validate every body/query with zod; parameterized queries (pg `$1`, Prisma, Drizzle); session cookies `httpOnly`, `secure`, `sameSite: 'lax'`; central error handler that hides stack traces in production.

## Plain PHP / WordPress

- PDO prepared statements; `password_hash($p, PASSWORD_ARGON2ID)`; `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')` on output; `session_set_cookie_params(['secure'=>true,'httponly'=>true,'samesite'=>'Lax'])`.
- WordPress: core/plugins/themes updated, remove unused plugins, `define('DISALLOW_FILE_EDIT', true);`, MFA for admins, limit login attempts, disable XML-RPC if unused, least-privilege DB user.

## Mobile (React Native / Expo / Flutter)

- `EXPO_PUBLIC_*` and anything in the bundle is public: no secrets in the app; call your backend.
- Tokens in SecureStore / Keychain / Keystore, not AsyncStorage/SharedPreferences.
- Backend enforces all authorization; consider certificate pinning for high-risk apps.

# Module E — Encryption (encrypt the site and its data)

Rules: never write custom crypto; use the platform's vetted library. Banned: base64 or hex as "encryption", ECB mode, static or reused IV/nonce, MD5 or SHA-1 for anything security-related, keys in source or in the same DB as the data.

- E1. In transit (public): TLS 1.2+ only (prefer 1.3), modern ciphers, auto-renewing certificates, HSTS with preload once stable. Verify with an SSL test and `curl -I http://` redirect.
- E2. In transit (internal): DB connections with TLS (e.g. `sslmode=verify-full`), Redis/queues over TLS, outbound webhooks over HTTPS; verify incoming webhook signatures (HMAC) with constant-time compare.
- E3. At rest (platform): enable disk, database, object-storage and backup encryption at the provider. Private files in storage are private buckets served by short-lived signed URLs.
- E4. Field-level encryption for every field in the sensitive data map below (national ID, phone, IBAN, address, health, documents, API tokens of users): XChaCha20-Poly1305 per E9, or AES-256-GCM, random nonce per value, AAD bound to the record (e.g. `user:<id>`), key version stored with the ciphertext. For fields that must be searchable, store a blind index (HMAC-SHA256 with a separate key) next to the ciphertext. Passwords are never encrypted, only hashed (control 5).
- E5. Key management: keys in a KMS or secret manager, loaded from env at runtime; 256-bit random (`openssl rand -base64 32`); separate keys per environment and per purpose (data, blind index, sessions); envelope encryption (per-tenant data key wrapped by a master key) for multi-tenant apps; documented rotation: add new version, encrypt new writes with it, re-encrypt old rows in a background job, then retire the old key.
- E6. Tokens and sessions: signing secrets >= 256-bit; pin the JWT algorithm (reject `none` and algorithm switching), short access-token lifetime, refresh-token rotation with reuse detection, revocation list or session table.
- E7. Backups and exports: encrypted, access-restricted, retention set; CSV/PDF exports of personal data generated on demand and served by expiring links.
- E8. Front-end code: production build minified, source maps not public, optional obfuscation for proprietary client logic, Subresource Integrity on third-party scripts. Tell the user plainly: anything shipped to the browser can be read; obfuscation only slows copying. Real secrets and business rules move to the server.

### Sensitive data map — encrypt by default

During DETECT, list every table/collection/file store and classify each field. Everything in the "Encrypt" rows is encrypted (E4/E9) unless the user explicitly opts out in writing.

| Class | Examples | Treatment |
|---|---|---|
| Identity | national ID / Iqama, passport, DOB, full address | Encrypt + blind index if searched |
| Contact | phone, personal email (when not the login key) | Encrypt + blind index |
| Login email | email used to sign in | Blind index for lookup + encrypted copy, or plaintext only if the user accepts the trade-off |
| Financial | IBAN, card last-4 + token (never full card numbers: use the payment provider), salary, invoices | Encrypt |
| Health / personal | medical notes, disability, family data | Encrypt |
| Documents | uploaded IDs, contracts, CVs, images of people | Encrypt the file (streaming AEAD) + private bucket |
| Secrets of users | OAuth/refresh tokens, integration API keys, webhook secrets, TOTP secrets | Encrypt |
| One-way only | passwords, recovery codes, reset tokens, API keys you issue | Hash (Argon2id or SHA-256 of a high-entropy token), never encrypt |
| Messages | private chats, support tickets with personal data | Encrypt when they may contain the above |
| Public | product names, prices, public posts | No encryption needed |

### E9. Maximum-strength profile (default in this skill)

- Cipher: XChaCha20-Poly1305 (libsodium) preferred: 192-bit random nonce removes nonce-collision risk at any volume and is fast without AES hardware. AES-256-GCM is acceptable with AES-NI; rotate a GCM key before 2^32 encryptions. Never AES-CBC/CTR without a MAC.
- Key hierarchy: master key (KEK) lives in a KMS/HSM or secret manager and never in code, repo or DB; per-tenant or per-table data keys stored wrapped; per-purpose sub-keys derived with HKDF-SHA256 (`info = "field:national_id"`), so one leaked sub-key exposes one field only.
- Context binding: AAD = table + record id (+ tenant id), so ciphertext copied to another row or user fails to decrypt.
- Least-privilege decryption: only the backend service that needs plaintext holds key access; DB admins, backups, logs, analytics and the front end see ciphertext only; log every decrypt of high-sensitivity classes.
- Passwords: Argon2id m=64 MiB, t=3, p=1 (floor: m=19 MiB, t=2), unique salt, plus a pepper (HMAC-SHA256 with a secret kept outside the DB) applied before hashing; rehash old hashes on login.
- Files: encrypt sensitive uploads before storage with libsodium secretstream (or AES-GCM per chunk), random file key wrapped by the data key.
- Transport: TLS 1.3 preferred, TLS 1.2 only with ECDHE + AEAD suites, HSTS preload, CAA DNS records; enable hybrid post-quantum key exchange (X25519MLKEM768) at the CDN/server when available.
- Hygiene: decrypt only at the point of use, never log or return plaintext sensitive fields in errors or analytics, mask in UIs (e.g. `•••• 4417`), wipe exports after expiry.
- Rotation: data keys yearly, immediately on suspected leak; prefix ciphertext with a key version; re-encrypt in background.
- State it plainly in the report: these ciphers cannot be brute-forced in practice; real breaches come from stolen keys, injection, broken access control or over-broad decrypt access, so E5/E9 key isolation and the 27 controls carry the real weight.

Maximum-strength reference (tested):

```js
// Node.js — XChaCha20-Poly1305 + HKDF sub-keys + peppered Argon2id
// npm i libsodium-wrappers argon2
import crypto from 'node:crypto';
import sodium from 'libsodium-wrappers';
import argon2 from 'argon2';
await sodium.ready;
const MASTER = Buffer.from(process.env.MASTER_KEY_B64, 'base64'); // 32 bytes, from KMS/secret manager
const subKey = (purpose) => Buffer.from(crypto.hkdfSync('sha256', MASTER, Buffer.alloc(0), purpose, 32));
export function seal(plain, purpose, aad) {
  const nonce = sodium.randombytes_buf(sodium.crypto_aead_xchacha20poly1305_ietf_NPUBBYTES);
  const ct = sodium.crypto_aead_xchacha20poly1305_ietf_encrypt(plain, aad, null, nonce, subKey(purpose));
  return ['x1', sodium.to_base64(nonce), sodium.to_base64(ct)].join(':');
}
export function open(blob, purpose, aad) {
  const [, n, ct] = blob.split(':');
  return sodium.to_string(sodium.crypto_aead_xchacha20poly1305_ietf_decrypt(null, sodium.from_base64(ct), aad, sodium.from_base64(n), subKey(purpose)));
}
const PEPPER = Buffer.from(process.env.PEPPER_B64, 'base64');
const pep = (pw) => crypto.createHmac('sha256', PEPPER).update(pw).digest();
```

# Module P — Active protection (keep attackers out)

- P1. Edge shield: put the site behind a CDN/WAF (e.g. Cloudflare or the host's WAF) with managed rules and DDoS protection; hide the origin IP; origin accepts traffic only from the CDN.
- P2. Bot protection: invisible challenge (e.g. Turnstile/hCaptcha/reCAPTCHA) on signup, login, reset, contact and checkout; honeypot field on public forms.
- P3. Admin hardening: MFA required for every admin; admin panel behind IP allow-list, VPN or SSO where possible; non-default admin path as an extra layer only; admin actions logged (control 8).
- P4. Account protection: minimum 12-character passwords, block breached passwords (k-anonymity range API), revoke all sessions on password change, notify on new-device login and email/password changes.
- P5. Backups: automated, encrypted (E7), off-site, versioned; restore tested before launch.
- P6. Incident readiness: alerts on spikes (control 8); a kill switch to revoke all sessions and rotate keys fast; `/.well-known/security.txt` with a contact; short runbook: contain, rotate, patch, notify.
- P7. Content protection: signed expiring URLs for private media, hotlink protection, robots rules do not hide sensitive paths (use auth instead).

Protection tests: origin IP direct request refused; form without challenge token rejected; admin login without MFA impossible; breached password rejected; backup restored to a scratch DB successfully.

# Module D — Intrusion detection and email alerts

Goal: when someone attacks the site, the owner gets an email saying what the attack was, where it came from, and what it targeted, while the request is blocked.

- D1. Detect: inspect URL, query and body for SQL injection, XSS, path traversal, command injection, SSRF and template injection; trap routes that real users never request (`/.env`, `/.git/`, `/wp-admin`, `/phpmyadmin`, backups) and answer them 404.
- D2. Detect behaviour: brute-force login (5 / 20 / 100 failures per IP in 15 min), access-denied events on other users' records or admin routes (IDOR attempts), CSRF and signature failures, rate-limit hits (control 12), webhook signature failures.
- D3. Honeytokens: plant a fake admin user, a fake API key in a decoy config and a fake row in sensitive tables; any use of them triggers an alert and means a leak.
- D4. Alert email contains: attack type, time (UTC), IP, approximate location (city/region/country), method and path, matched pattern (masked), user agent, logged-in user if any, and the recommended action. Secrets, passwords, cookies and tokens are masked; never include full request bodies.
- D5. Location: read CDN geo headers (Cloudflare `CF-IPCountry`, `CF-IPCity`, `CF-Region` via "Add visitor location headers"; Vercel `x-vercel-ip-country`; CloudFront `CloudFront-Viewer-Country`) or a local GeoIP database (MaxMind GeoLite2). Take the client IP only from the trusted proxy header (`CF-Connecting-IP`, or `X-Forwarded-For` with trust-proxy set to the real hop count), never from a header the client can forge.
- D6. Noise control: one email per IP per attack type per 10 minutes, every event still logged; optional daily digest; `GUARD_MODE=monitor` (log + email, no blocking) for the first days to tune false positives, then `block`.
- D7. Delivery: SMTP from a dedicated sender (e.g. `security@yourdomain`) with SPF/DKIM, or a transactional email API; credentials in env; alert recipient in `ALERT_TO`; optional second channel (Telegram/Slack/WhatsApp webhook) for critical events (honeytoken, admin login from a new country).
- D8. Response: repeated or high-severity attackers are blocked at the WAF (P1) automatically or by the owner; never counter-attack or scan the attacker's systems.
- D9. Edge alerts: also enable the CDN/WAF's own notifications (e.g. Cloudflare security event and DDoS alerts) so attacks stopped before reaching the app are reported too.

Tell the user plainly: IP location is approximate and attackers often use VPNs, Tor or cloud servers, so the location shows where the traffic came from, not who the person is. Pattern rules catch common automated attacks, not every attack; they complement the 27 controls, they do not replace them.

Env: `ALERT_TO`, `ALERT_FROM`, and `ALERT_SMTP_URL` (Node, e.g. `smtps://user:pass@smtp.host:465`) or `ALERT_SMTP_HOST/PORT/USER/PASS` (Python); `GUARD_MODE=monitor|block`.

Detection tests: normal search, an apostrophe name (O'Reilly) and text with `--` pass; `' OR 1=1 --`, `<script>`, `../../etc/passwd` and `/.env` are blocked and produce one email with type, IP and location; a second identical attack within 10 minutes is logged but not emailed; 5 failed logins produce a brute-force alert.

```js
export function guard() {
  return async (req, res, next) => {
    try {
      const path = decodeURIComponent(req.path || '');
      if (TRAPS.test(path)) { await alert(req, 'Probe for sensitive file', path); return res.status(404).end(); }
      const haystack = [req.originalUrl, JSON.stringify(req.query || {}), JSON.stringify(req.body || {})].join(' ');
      let decoded = haystack; try { decoded = decodeURIComponent(haystack); } catch {}
      for (const [type, re] of RULES) {
        const m = decoded.match(re);
        if (m) { await alert(req, type, m[0]); if (BLOCK) return res.status(400).json({ error: 'Bad request' }); break; }
      }

    next();
  };
}
```

# Module A — AI application security (LLM apps, RAG, agents, MCP)

Apply when the project calls an LLM (OpenAI, Anthropic, Gemini, local models), has RAG/vector search, chatbots, AI agents, tool calling or MCP servers. Mapped to the OWASP GenAI LLM Top 10 2026 (LLM01–LLM10).

Core rule: the model will be fooled. Every guarantee must be enforced in code (auth, filters, limits, approvals), never only by instructions in a prompt.

- A1. Prompt injection (LLM01). Treat user messages AND everything the model reads (uploaded files, web pages, emails, tickets, RAG chunks, tool results) as untrusted data. System prompt is static: never concatenate user input into it. Put untrusted content in the user turn inside clear delimiters (`<documents>…</documents>`) with an instruction that it is data. Injection cannot be fully filtered, so A3 and A10 limit the damage.
- A2. Sensitive information disclosure (LLM02). Never put secrets, other users' data or internal-only data in prompts. Retrieval is filtered by the signed-in user/tenant in the database query, not by asking the model. Redact or tokenize national IDs, phones, IBANs before sending to a third-party model when the task allows. Check the provider's data-retention and training settings; sending personal data to a foreign API is a cross-border transfer (Module K).
- A3. Excessive agency (LLM03). Least privilege for tools: read-only by default, explicit allow-list, narrow parameters (e.g. `get_order(order_id)` not `run_sql(query)`). Tools act with the signed-in user's permissions, never an admin token. Human confirmation for anything that sends, pays, deletes, publishes or changes permissions. MCP servers: install only from trusted sources, pin versions, review tool descriptions, give each its own scoped credentials, restrict filesystem/network access, never expose a local MCP server to the internet without auth.
- A4. Supply chain (LLM04). Pin model IDs and SDK versions; review third-party prompts, agents, plugins and MCP servers before use; load model weights only from trusted sources and prefer `safetensors` over pickle formats; no `curl | bash` installers in production.
- A5. Data and model poisoning (LLM05). Control who can write to the knowledge base, fine-tuning data and memory; record provenance (source, uploader, date) per chunk; review or quarantine bulk/anonymous uploads before indexing.
- A6. Unbounded consumption (LLM06). AI endpoints require login; per-user and global rate limits and daily quotas; cap input length and `max_tokens`; timeouts and max tool-call loops for agents; hard spend limit and budget alerts at the provider; cache repeated answers; a kill switch env flag that disables AI features. The provider key lives only on the server (control 2).
- A7. Misinformation (LLM07). Ground answers in retrieved sources and show citations; say "I don't know" when retrieval is empty; disclaimers and human review for medical, legal, financial or safety-relevant output.
- A8. Hidden context exposure (LLM08). Assume the system prompt, hidden instructions and retrieved context can be extracted. Keep credentials, internal URLs, other users' data and business secrets out of them; authorization never depends on the prompt staying secret.
- A9. Vector and embedding weaknesses (LLM09). Tenant isolation in the vector store (separate namespace/collection or a mandatory tenant filter added server-side); access control on stored chunks; encrypt chunks that contain sensitive data (Module E); delete embeddings when the source document or user is deleted.
- A10. Improper output handling (LLM10). Model output is untrusted input: escape before rendering HTML; sanitize Markdown (block raw HTML, `javascript:` links, and auto-loading images to unknown domains, a common data-exfiltration trick); never pass output to `eval`, SQL, shell, file paths or redirects; validate structured output against a schema before acting on it.
- A11. Monitoring. Log prompts and outputs with PII redaction and a retention limit; feed suspicious events (repeated injection phrases, tool-call denials, quota hits, cost spikes) into Module D alerts in monitor mode.

# Module K — Saudi PDPL compliance (technical checklist)

Apply when the site processes personal data of people in Saudi Arabia. The PDPL applies to entities in the Kingdom and to entities outside it that process personal data of individuals in the Kingdom. Regulator: SDAIA. This module turns legal duties into engineering tasks; it is not legal advice. Have a qualified advisor confirm current obligations, especially for health, financial (SAMA) or government (NCA) contexts, which add sector rules.

Status note (re-check before relying on it): SDAIA ran a public consultation (October to 5 November 2026) on amendments to the Implementing Regulations, proposing data localisation, breach notification within 72 hours in all cases, stricter DPIA/DPO/registration duties and Arabic privacy policies. Build to the stricter proposed standard where it is cheap to do so.

- K1. Data inventory: a record of processing (what personal data, where stored, why, legal basis, retention, who can access, which vendors receive it). Reuse the Module E sensitive data map.
- K2. Legal basis and consent: store consent records (user, timestamp, policy version, purpose, channel); separate, unticked consent for marketing; withdrawing consent as easy as giving it; stop processing on withdrawal.
- K3. Privacy notice: shown before or at collection, available in Arabic (and other languages you serve): purposes, data categories, retention, recipients and transfers, rights and how to exercise them, contact (DPO if appointed).
- K4. Data subject rights: in-app or verified-request flows to access/receive a copy (readable export), correct, and delete/destroy personal data; verify identity first; log each request and response date; respond within the deadline in the Implementing Regulations (confirm the current period).
- K5. Minimization and retention: collect only fields you use; retention period per data class; scheduled job that deletes or anonymizes expired data, including backups on rotation, logs and embeddings (A9).
- K6. Security: the 27 controls plus Modules E, P, D are the technical safeguards; restrict staff access by role and log access to personal data.
- K7. Breach response: when a breach may harm data subjects, notify SDAIA within 72 hours of becoming aware (through the National Data Governance Portal) and notify affected individuals without undue delay. Engineering: Module D alerts record the "first aware" timestamp; a runbook with owner, SDAIA submission template (what happened, data categories, number affected, measures taken, contact), and a user notification template in Arabic. Under the proposed amendments the 72-hour duty would apply to every breach regardless of harm: plan for that.
- K8. Cross-border transfers: list every place personal data leaves the Kingdom: hosting region, database/backup region, email/SMS providers, analytics, error tracking, CDNs and AI model APIs. Transfers are governed by the Regulation on Personal Data Transfer outside the Kingdom (2024) with tools such as Standard Contractual Clauses, plus SDAIA's transfer risk-assessment guideline (2025). Prefer in-Kingdom hosting regions for databases and backups, minimize/redact data sent to foreign APIs, and document the transfer basis. The proposed amendments would add a general in-Kingdom storage requirement.
- K9. Processors: data processing agreements with every vendor that touches personal data; vendor list kept current.
- K10. Governance: check whether you must register in the National Register of Controllers and appoint a Personal Data Protection Officer under SDAIA's rules; run a DPIA for high-risk processing (sensitive data, large scale, profiling, new tech such as AI on personal data).
- K11. Direct marketing: prior consent, clear sender identity, one-click unsubscribe honored promptly.
- K12. Training and records: staff who handle personal data are trained; keep evidence (policies, consent logs, DPIAs, breach log) ready for SDAIA.

Report section: a K1–K12 table with Done / Partial / Missing / Needs legal confirmation, plus the list of data flows leaving the Kingdom.

Sources: SDAIA PDPL and Implementing Regulations (2023); Regulation on Personal Data Transfer outside the Kingdom (Sept 2024) and Standard Contractual Clauses; SDAIA transfer risk assessment guideline (Feb 2025); SDAIA draft amendments consultation (Oct 2026). Verify the current texts on sdaia.gov.sa and dgp.sdaia.gov.sa.

```python
#!/usr/bin/env python3
"""vibe-security-hardening scanner. Stdlib only, Python 3.8+.  vibe-scan: ignore-file

Usage:

Suppress a reviewed false positive: add "vibe-scan: ignore" on that line, or "vibe-scan: ignore-file" near the top of a file.

Scans YOUR OWN project: leaked secrets (files + git history), exposed/tracked sensitive files,
public env misuse, dangerous code patterns, missing RLS/rules, dependency audit, and (with --url)
live headers, cookies, CORS, HTTPS and exposed paths. Secret values are never printed (last 4 chars only).

CODE = [(c, n, re.compile(p, re.M), s) for c, n, p, s in CODE]
CODE_EXT = {".js", ".jsx", ".ts", ".tsx", ".mjs", ".cjs", ".vue", ".svelte", ".py", ".php", ".rb", ".go", ".java",
            ".cs", ".kt", ".rules", ".json", ".html", ".erb", ".blade.php", ".twig", ".env", ".yml", ".yaml", ".ini", ".cfg", ".toml"}

PUBLIC_PREFIX = re.compile(r"\b(NEXT_PUBLIC_|VITE_|REACT_APP_|PUBLIC_|EXPO_PUBLIC_|NUXT_PUBLIC_|GATSBY_)([A-Z0-9_]*(SECRET|SERVICE_ROLE|PRIVATE|PASSWORD|PASSWD|DATABASE_URL|DB_URL|SK_|ADMIN|WEBHOOK)[A-Z0-9_]*)")

findings = []

IGNORED_LINES = {}

def add(control, sev, title, where="", detail=""):
    if ":" in where and not where.startswith(("http", "commit")):
        f, _, ln = where.rpartition(":")
        if ln.isdigit() and int(ln) in IGNORED_LINES.get(f, ()):
            return
    findings.append({"control": control, "severity": sev, "title": title, "where": where, "detail": detail})

def mask(v):
    v = str(v)
    return ("…" + v[-4:]) if len(v) > 4 else "****"

def iter_files(root):
    for dp, dns, fns in os.walk(root):
        dns[:] = [d for d in dns if d not in SKIP_DIRS and not d.startswith(".cache")]
        for fn in fns:
            p = os.path.join(dp, fn)
            low = fn.lower()
            if any(low.endswith(e) for e in SKIP_EXT) or low in ("package-lock.json", "yarn.lock", "pnpm-lock.yaml", "poetry.lock", "composer.lock"):
                continue
            try:
                if os.path.getsize(p) > MAX_FILE:
                    continue
            except OSError:
                continue
            yield p

def read(p):
    try:
        with open(p, "r", encoding="utf-8", errors="ignore") as f:
            return f.read()
    except OSError:
        return ""

def scan_secrets(text, where, control="C2", in_history=False):
    for name, rx, sev in SECRETS:
        for m in rx.finditer(text):
            val = m.group(m.lastindex) if name == "Hardcoded secret assignment" and m.lastindex else m.group(0)
            ctx = text[max(0, m.start() - 40): m.end() + 10]
            if PLACEHOLDER.search(val) or (name == "Hardcoded secret assignment" and PLACEHOLDER.search(ctx)):
                continue
            ln = text.count("\n", 0, m.start()) + 1
            add("C24" if in_history else control, sev, ("Secret in git history: " if in_history else "Secret in file: ") + name,
                where if in_history else f"{where}:{ln}", f"value {mask(val)} — revoke and rotate it (C25)")

def scan_files(root):
    for p in iter_files(root):
        rel = os.path.relpath(p, root)
        text = read(p)
        if not text or "vibe-scan: ignore-file" in text[:600]:
            continue
        if "vibe-scan: ignore" in text:
            IGNORED_LINES[rel] = {i + 1 for i, l in enumerate(text.splitlines()) if "vibe-scan: ignore" in l}
        scan_secrets(text, rel)
        ext = os.path.splitext(p)[1].lower()
        if ext in CODE_EXT or rel.endswith(".rules") or os.path.basename(p).startswith(".env"):
            for control, name, rx, sev in CODE:
                for m in rx.finditer(text):
                    ln = text.count("\n", 0, m.start()) + 1
                    add(control, sev, name, f"{rel}:{ln}", m.group(0)[:80].strip())
        for m in PUBLIC_PREFIX.finditer(text):
            ln = text.count("\n", 0, m.start()) + 1
            add("C11", "critical", "Secret-looking variable exposed to the browser via public prefix", f"{rel}:{ln}", m.group(0))
        if ext == ".sql" or "/migrations/" in rel.replace("\\", "/"):
            tables = re.findall(r"(?i)create\s+table\s+(if\s+not\s+exists\s+)?([\"\w.]+)", text)
            for _, t in tables:
                tn = t.strip('"').split(".")[-1]
                if not re.search(r"(?i)alter\s+table\s+[\"\w.]*" + re.escape(tn) + r"[\"]?\s+enable\s+row\s+level\s+security", text):
                    add("C3", "high", f"Table '{tn}' created without ENABLE ROW LEVEL SECURITY in this file", rel,
                        "verify RLS is enabled elsewhere, with policies per role")

def git(root, *args):
    try:
        return subprocess.run(["git", "-C", root, *args], capture_output=True, text=True, timeout=120).stdout
    except Exception:
        return ""

def scan_git(root, history=True):
    if not os.path.isdir(os.path.join(root, ".git")) or not shutil.which("git"):
        add("C24", "info", "Not a git repository or git not installed; history scan skipped")
        return
    for f in git(root, "ls-files").splitlines():
        if SENSITIVE_TRACKED.search(f):
            add("C11" if ".env" in f else "C23", "critical", "Sensitive file is tracked by git", f, "remove from repo, add to .gitignore, rotate any secret it contained")
    gi = read(os.path.join(root, ".gitignore"))
    if ".env" not in gi:
        add("C11", "high", ".env is not in .gitignore", ".gitignore")
    if history:
        log = git(root, "log", "-p", "--all", "--no-color", "-U0", "--max-count=2000")
        commit = ""
        chunk = []
        for line in log.splitlines():
            if line.startswith("commit "):
                if chunk:
                    scan_secrets("\n".join(chunk), f"commit {commit[:10]}", in_history=True)
                commit, chunk = line.split()[1], []
            elif line.startswith("+") and not line.startswith("+++"):
                chunk.append(line[1:])
        if chunk:
            scan_secrets("\n".join(chunk), f"commit {commit[:10]}", in_history=True)

def audit_deps(root):
    ran = False
    if os.path.exists(os.path.join(root, "package-lock.json")) and shutil.which("npm"):
        ran = True
        try:
            out = subprocess.run(["npm", "audit", "--json", "--omit=dev"], cwd=root, capture_output=True, text=True, timeout=180).stdout
            v = json.loads(out or "{}").get("metadata", {}).get("vulnerabilities", {})
            for level in ("critical", "high"):
                if v.get(level):
                    add("C21", level, f"npm audit: {v[level]} {level} vulnerable dependencies", "package-lock.json", "run npm audit fix / upgrade")
        except Exception as e:
            add("C21", "info", "npm audit failed", "", str(e)[:120])
    for req in ("requirements.txt", "pyproject.toml"):
        if os.path.exists(os.path.join(root, req)):
            ran = True
            if shutil.which("pip-audit"):
                r = subprocess.run(["pip-audit", "-r", req] if req.endswith(".txt") else ["pip-audit"], cwd=root, capture_output=True, text=True, timeout=300)
                if r.returncode not in (0,):
                    add("C21", "high", "pip-audit reported vulnerable Python packages", req, (r.stdout or r.stderr)[-300:])
            else:
                add("C21", "info", "pip-audit not installed; Python dependency audit skipped", req, "pip install pip-audit")
            break
    if os.path.exists(os.path.join(root, "composer.lock")) and shutil.which("composer"):
        ran = True
        r = subprocess.run(["composer", "audit", "--no-interaction"], cwd=root, capture_output=True, text=True, timeout=180)
        if r.returncode != 0:
            add("C21", "high", "composer audit reported vulnerable packages", "composer.lock", r.stdout[-300:])
    if not ran:
        add("C21", "info", "No supported lockfile/tool found; dependency audit skipped")

def http(url, method="GET", headers=None, follow=True):
    ctx = ssl.create_default_context()
    req = urllib.request.Request(url, method=method, headers={"User-Agent": "vibe-security-scan/1.0", **(headers or {})})
    opener = urllib.request.build_opener(urllib.request.HTTPSHandler(context=ctx)) if follow else \
        urllib.request.build_opener(urllib.request.HTTPSHandler(context=ctx), NoRedirect())
    try:
        r = opener.open(req, timeout=15)
        return r.status, dict(r.headers), r.read(2048)
    except urllib.error.HTTPError as e:
        return e.code, dict(e.headers or {}), b""
    except Exception as e:
        return None, {}, str(e).encode()

class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, *a, **k):
        return None

def scan_url(url):
    url = url.rstrip("/")
    if not re.match(r"^https?://", url):
        url = "https://" + url
    base = url
    host = re.sub(r"^https?://", "", url)
    if url.startswith("https://"):
        st, h, _ = http("http://" + host + "/", follow=False)
        loc = {k.lower(): v for k, v in h.items()}.get("location", "")
        if st and not (300 <= st < 400 and loc.startswith("https://")):
            add("C4", "high", "HTTP does not redirect to HTTPS", "http://" + host, f"status {st}")
    else:
        add("C4", "high", "Site scanned over plain HTTP", url, "use HTTPS in production")
    st, h, body = http(base + "/")
    if st is None:
        add("C4", "high", "Request to site failed", url, body.decode(errors="ignore")[:150])
        return
    hl = {k.lower(): v for k, v in h.items()}
    need = {"strict-transport-security": "C4", "content-security-policy": "C14", "x-content-type-options": "C14",
            "referrer-policy": "C14", "permissions-policy": "C14"}
    for name, c in need.items():
        if name not in hl:
            add(c, "medium" if name != "strict-transport-security" else "high", f"Missing header: {name}", url)
    if "x-frame-options" not in hl and "frame-ancestors" not in hl.get("content-security-policy", ""):
        add("C14", "medium", "Missing clickjacking protection (X-Frame-Options or CSP frame-ancestors)", url)
    hsts = hl.get("strict-transport-security", "")
    m = re.search(r"max-age=(\d+)", hsts)
    if hsts and (not m or int(m.group(1)) < 15552000):
        add("C4", "low", "HSTS max-age below 180 days", url, hsts)
    for leak in ("x-powered-by", "server"):
        if leak in hl and re.search(r"\d", hl[leak]):
            add("C14", "low", f"Version disclosed in {leak} header", url, hl[leak])
    for k, v in h.items():
        if k.lower() == "set-cookie":
            for cookie in v.split("\n"):
                low = cookie.lower()
                miss = [f for f in ("httponly", "secure", "samesite") if f not in low]
                if miss:
                    add("C15", "medium", "Cookie missing flags: " + ", ".join(miss), url, cookie.split("=")[0])
    st, h, _ = http(base + "/", headers={"Origin": "https://evil.example"})
    hl = {k.lower(): v for k, v in h.items()}
    acao = hl.get("access-control-allow-origin", "")
    if acao in ("*", "https://evil.example"):
        sev = "high" if hl.get("access-control-allow-credentials", "").lower() == "true" or acao == "https://evil.example" else "medium"
        add("C13", sev, "CORS accepts an arbitrary origin", url, f"ACAO={acao}")
    for path in ("/.env", "/.env.local", "/.git/config", "/.git/HEAD", "/backup.zip", "/backup.sql", "/db.sql", "/.DS_Store",
                 "/wp-config.php.bak", "/config.json", "/phpinfo.php", "/server-status", "/.vscode/settings.json", "/docker-compose.yml"):
        st, _, body = http(base + path, follow=False)
        if st == 200 and body and b"<html" not in body[:300].lower():
            add("C23", "critical", "Sensitive path publicly accessible", base + path, "block it at the server/CDN")
    for path in ("/api/docs", "/swagger", "/graphql?query=%7B__schema%7Btypes%7Bname%7D%7D%7D"):
        st, _, body = http(base + path)
        if st == 200 and (b"swagger" in body.lower() or b"__schema" in body or b"openapi" in body.lower()):
            add("C20", "medium", "API docs or GraphQL introspection exposed in production", base + path)
    st, _, _ = http(base + "/.well-known/security.txt")
    if st != 200:
        add("P6", "low", "No /.well-known/security.txt", url)

def main():
    ap = argparse.ArgumentParser(description="vibe-security-hardening scanner")
    ap.add_argument("path", nargs="?", default=".")
    ap.add_argument("--url", help="your own live site, e.g. https://example.com")
    ap.add_argument("--json", help="write JSON report to this file")
    ap.add_argument("--fail-on", default="critical", choices=list(SEV))
    ap.add_argument("--no-history", action="store_true")
    ap.add_argument("--no-deps", action="store_true")
    a = ap.parse_args()
    root = os.path.abspath(a.path)
    scan_files(root)
    scan_git(root, history=not a.no_history)
    if not a.no_deps:
        audit_deps(root)
    if a.url:
        scan_url(a.url)
    seen, uniq = set(), []
    for f in findings:
        k = (f["control"], f["title"], f["where"])
        if k not in seen:
            seen.add(k)
            uniq.append(f)
    uniq.sort(key=lambda f: (-SEV[f["severity"]], f["control"], f["where"]))
    counts = {s: sum(1 for f in uniq if f["severity"] == s) for s in SEV}
    print(f"vibe-security-hardening scan: {root}" + (f"  url: {a.url}" if a.url else ""))
    print("summary: " + "  ".join(f"{s}={counts[s]}" for s in SEV))
    for f in uniq:
        print(f"[{f['severity'].upper():8}] {f['control']:4} {f['title']}" + (f"  @ {f['where']}" if f['where'] else "") + (f"  — {f['detail']}" if f['detail'] else ""))
    if a.json:
        with open(a.json, "w", encoding="utf-8") as fh:
            json.dump({"root": root, "url": a.url, "summary": counts, "findings": uniq}, fh, indent=2, ensure_ascii=False)
    worst = max([SEV[f["severity"]] for f in uniq] or [0])
    sys.exit(1 if worst >= SEV[a.fail_on] and worst > 0 else 0)

if __name__ == "__main__":
    main()
```
